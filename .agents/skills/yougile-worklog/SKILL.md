# Учёт времени в YouGile

Запись — сообщение в чате задачи от пользователя подключённого MCP, а не изменение поля «Факт». Вызывай инструменты сервера `yougile` по имени операции в каталоге текущего клиента.

## Задача и время

1. Запусти из корня проекта `node .agents/skills/yougile-worklog/time.cjs status`. Для остальных команд используй тот же файл. Состояние общее для клиентов этого пользователя компьютера; активная задача таймера не меняется при смене папки.
2. Для старта или ручного ввода разреши ссылку или короткий ID через `get_task_data`. При наличии только названия используй `search_tasks`, включая задачи без доски. При неоднозначности предложи выбрать. Возьми UUID `id` и актуальный `taskId` карточки. Не создавай задачу, чтобы записать время, без явного запроса.
3. Выбери команду:

   | Запрос | Аргументы CLI |
   | --- | --- |
   | Записать фактическое время | `manual <uuid> <taskId> <целые минуты> [YYYY-MM-DD]` |
   | Начать таймер | `start <uuid> <taskId>` |
   | Сделать перерыв / продолжить | `pause` / `resume` |
   | Сколько прошло? | `status` |
   | Закончить и записать | `stop` |
   | Отменить таймер без записи | `cancel-timer` |

   «1,5 часа» — 90 минут. Если длительность не названа и нет таймера, спроси её. Не выводи трудозатраты из истории Git или длительности диалога. При ручной записи на задачу активного таймера уточни, заменяет ли она интервал. При переходе через полночь уточни дату или разбивку. Дата таймера по умолчанию — день старта, ручной записи — сегодня по местным часам. Перерывы исключаются, округление до ближайшей минуты.

## Доставка

`manual` и `stop` готовят `pending`. По просьбе лишь посчитать или подготовить покажи черновик; не отправляй его. Просьба записать часы подтверждает отправку. При повторном запросе проверь `pending` и квитанцию `last`, чтобы отличить повтор от нового интервала.

1. Прочитай чат `pending.task` через `get_task_data`. Ищи точный маркер `[time:<pending.id>]`. При восстановлении проверяй страницы с `cursor` до нахождения маркера или конца переписки.
2. Если запись найдена, выполни `ack <pending.id> <messageId>` и не публикуй её повторно. Иначе выполни `claim <pending.id>`: только успешный захват разрешает отправку.
3. Вызови `send_chat_message` с `chatId=pending.task`, `text=pending.text`, `textHtml=null`, `attachmentUrls=null`. По возвращённому `messageId` выполни `ack <pending.id> <messageId>`. Сообщи пользователю ID задачи, дату и длительность. Если отдельно попросили комментарий, отправь его отдельно после подтверждения записи часов.
4. При отсутствии MCP или прав записи оставь `pending`. При таймауте либо `sending=true` проверь маркер. Если его нет, старый запрос уже закончился и пользователь подтвердил повтор, выполни `reset-send <pending.id>` и снова начни с проверки чата. Не выдавай неопределённый результат за успех. Для согласованной замены неотправленного черновика используй `discard <pending.id>`, затем `manual`.
